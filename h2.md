## a) Break into 010-staff-only

- Ensimmäisenä ladataan teron sivulta tarvittavat ohjelmat tämän tehtävän suorittamiseen

```bash
$ wget https://terokarvinen.com/hack-n-fix/teros-challenges.zip
$ unzip teros-challenges.zip
$ sudo apt install wget unzip python3-flask python3-flask-sqlalchemy
```
- Tästä päästään sitten katsomaan teron sivua joka pitääkin hackeroida.
- Sivulla kokeilin aluksi monta eri tuttua menetelmää. Kuten url-osoitteen päätteeseen admin, adminstrator yms. mutta millään näillä ei päässyt eteenpäin. Syöte-kenttää koitin myös laittaa adminia ja muuta komentoa mutta ottaa vain numeroita alustavasti.
- Aloin katsomaan DevToolsilla sivun koodia ja sen pystyi muokkaamaan.
<img width="480" height="107" alt="image" src="https://github.com/user-attachments/assets/25012472-0f65-4197-bf75-92bcde7e5538" />

- Tässä muokkasin input type "numerosta" tekstiksi. Jolloin pystyy antamaan kenttään tekstiä. Tässä aloin kokeilemaan erilaisia ' OR 1=1' injektioita mutta sitten törmäsin server erroriin. Eli syötin jotain joka rikkoi sivun.
<img width="1001" height="645" alt="{00635DBB-01F4-429D-98D0-5416D233951D}" src="https://github.com/user-attachments/assets/db46e33b-7bcb-4fcf-a163-b32a7618157a" />
- Kävin tarkemmin terminaalista katsomassa mikäs tämän aiheutti.
<img width="582" height="112" alt="image" src="https://github.com/user-attachments/assets/61e8552f-bcfd-4a80-9aeb-bb9a32e185f8" />

- Eli pientä erroria siellä.

- Jatkoin tehtävän tekemistä syöttämällä input kenttää tekstiä ja sain lopulta sen ratkottua. Syötin input kenttään ``` 'OR password LIKE '%SUPERADMIN%' -- ``` Tällä sai lopullisen vastauksen.

## b) Fix the 010-staff-only vulnerability
- Aloitin tutkimaan sivun lähdekoodia ja pohdin, että jotenkin täytyy estää käyttäjä ajamasta SQL koodia.
- Sieltä löytyi tämä osio koodista joka käsittelee salasanan pin koodia.

<img width="615" height="42" alt="image" src="https://github.com/user-attachments/assets/a95c9922-fbd0-4075-b6ce-72a953c1d7eb" />

- Hieman muutetaan koodia.
<img width="622" height="100" alt="image" src="https://github.com/user-attachments/assets/54c56eab-672a-4890-af1a-34118fd4e7e5" />

- Ja testaan samaa aikasempaa SQL- injektiota mutta tällä kertaa se antaa tämän.
  
<img width="777" height="372" alt="image" src="https://github.com/user-attachments/assets/550d42db-3280-4901-ae5a-5b48e60aaa52" />

- Eli alkuperäinen koodi oli rakennettu siten, että käyttäjän annettu tieto oli suoraan laitettu "stringiin". Tällöin se kaikki käyttäjän antama syötetään suoraan SQL- injektioksi. Tämän koodin korjauksen jälkeen niin käyttäjän antama data ja SQL- injektiot pidetään täysin erillään. Eli käyttäjän antama input ei tule yhteen sivun koodin kanssa.

## c) Solve dirfuzt-1
- Latasin **dirfuzt-1** ohjelman ja ajoin sen saadakseni nettisivun päälle ja tämän osoitteen.
<img width="692" height="145" alt="image" src="https://github.com/user-attachments/assets/1cd8b64e-d960-460f-89d5-c6535822aa97" />

- Sitten latasin **ffuf** ohjelman ja **Seclistan**

```bash
$ sudo apt-get update
$ sudo apt-get install ffuf
$ wget https://raw.githubusercontent.com/danielmiessler/SecLists/master/Discovery/Web-Content/common.txt
```

- Tämän jälkeen päästään ajamaan ffuf komentoa ja käyttäen seclistaa. Mutta pelkästään tämän suorittamien antoi niin monta mahdollista vastausta joten rajasin vaihtoehtoja.

<img width="891" height="601" alt="image" src="https://github.com/user-attachments/assets/089bad4e-1a59-483a-951a-44b695a2d29a" />

- Tarkemmin halusimme löytää kaksi asiaa eli **admin sivu** sekä **versionhallinta sivu**. Joten päätellään annetuista vastauksista tuo **wp-admin** ja **.git**. Joten käydään katsomassa sivulta.
